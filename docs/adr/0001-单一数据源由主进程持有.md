分组、标签页、会话栈只存一份，由主进程持有并写盘（userData/store.json），渲染进程只读取快照、通过 IPC 发操作。此前同一份会话栈在内存标签、已保存分组快照、已保存工作区快照、workspace.json、标签历史里各有一份，靠多套同步规则互相拉齐，"误标脏""备注丢失"等问题反复出现；会话开始事件本来就先到主进程，退出前写盘也只能在主进程保证，所以选主进程作为唯一持有方。

# Consequences

- 每次操作立即全量原子写（临时文件 + 改名），不再有延迟合并，退出时无需额外刷盘。
- 关闭的标签页不删除，带关闭时间留在同一棵树里，即历史标签页；不再有"保存"动作和"未保存"状态。
- 会话栈按 SessionStart 的来历（startup / clear / fork / compact / resume）在主进程维护，渲染进程不再自行压栈。
